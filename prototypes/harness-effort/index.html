How each harness takes a reasoning effort

Four lanes, one question each: where does the effort enter, which words does the lane accept, where does it read back, how does a wrong value fail, and can it change on a resume. Every claim is read off a live run's request body, captured by a stand-in model server. The pane never judges itself.

The rig claude codex opencode pi Summary

1 The rig

Each probe spawns the real CLI in a detached tmux pane through drive.mjs, the daemon's own paced write path. The CLI talks to a local stand-in model server (standin-anthropic.mjs, standin-responses.mjs, standin-chat.mjs) that logs every request whole. So the effort a spawn states is proven on the wire, and the pane captures show only where a human can read it back. Raw captures sit in evidence/.

2 claude 2.1.220 PROVEN

A spawn flag, five levels, a per-turn transcript record, and a warning instead of a refusal. The wire field is output_config.effort on POST /v1/messages.

  • Mechanism: claude --effort xhigh at spawn. The env var CLAUDE_CODE_EFFORT_LEVEL works too (req-18 sent low off the env var alone). A settings.json key named effort does nothing (req-16).
  • Vocabulary: low medium high xhigh max — the daemon's union minus ultra, one to one. Hidden extra: --effort ultracode is accepted and rides the wire as xhigh (req-14).
  • Default: high, proven by the no-flag resume (req-8) and the invalid-value fallback (req-12).
  • Mid-session: the /effort slider. The next turn sends the new value (req-6). The switch is session-only: a bare --continue falls back to high (req-8), and --continue --effort low wins (req-10). So an override applies on every spawn, resume included.

3 codex 0.146.0 PROVEN

The known config key, a seventh word, and two traps: garbage passes through, and ultra lies on the readback. The wire field is reasoning.effort on POST /v1/responses.

  • Mechanism: model_reasoning_effort in config.toml (what workspace.mjs writes today), or per spawn as -c model_reasoning_effort="x".
  • Vocabulary: minimal low medium high xhigh max ultra. The picker names Max and Ultra "Advanced Reasoning · consumes usage limits faster", Ultra "for demanding work using multiple agents". minimal sits below the union's floor. ultra matches the union by name — but see the trap.
  • Default: per model, not one constant. The picker marks Low as the default for gpt-5.6-sol. routing.yaml already records gpt-5.5 defaulting to medium.
  • Mid-session: the /model picker switches effort per session (req-11) and never writes config.toml.

4 opencode 1.18.18 PROVEN

The config IS the vocabulary: curia authors the effort words, and the TUI spawn reads them from the throwaway opencode.json. Installed pinned after the operator's approval. The wire field is reasoning_effort on POST /v1/chat/completions.

  • Mechanism: the model entry's base options — models.<id>.options.reasoningEffort — state the spawn effort (req-45). The entry can declare variants (name → overrides), picked per run with run --variant or mid-session with /variant. The TUI takes no variant flag at spawn; a top-level variant key and default: true on a variant both do nothing (proven on the wire).
  • Vocabulary: config-defined. Whatever string the config states rides verbatim — ultra included (req-34). The union maps trivially because curia writes the mapping itself.
  • Default: none. No option, no effort field on the wire.
  • Resume: --continue re-reads the config, so a changed reasoningEffort applies to the resumed session (req-46). A ticket-type override on resume = rewrite the throwaway config.

5 pi 0.84.2 PROVEN

A validated flag, the one always-visible footer, and a per-change session record. Installed pinned after the operator's approval (@earendil-works/pi-coding-agent). The wire field is reasoning_effort, mapped per model through thinkingLevelMap in models.json.

  • Mechanism: --thinking <level> at spawn, or the suffix --model <id>:<level> (req-11). The per-model thinkingLevelMap translates each level to the provider string.
  • Vocabulary: fixed and validated: off minimal low medium high xhigh max. low..max match the union. ultra is INVALID on pi. off and minimal sit below the union's floor.
  • Default: medium (req-10). off omits the field (req-2).
  • Mid-session: Shift+Tab cycles the level, footer and wire follow (req-13). No /thinking command — that text goes to the model as a message. Session-only: a bare -c resume returns to medium even after xhigh (req-19), and --thinking on the resume wins (req-17). The flag rides every spawn.

What #533 can settle. All four lanes take the effort at spawn from a value the daemon controls, and the override survives a resume on each — claude and pi by the flag on the resume spawn, opencode by rewriting the throwaway config, codex only by -c on the resume command. So defaults.<type> as {model, effort} with type-beats-model precedence is implementable everywhere.
No lane refuses a wrong value. claude and pi warn and fall back. codex and opencode send garbage to the wire — a mid-run 400 on a real API. The daemon's boot check against REASONING_EFFORTS is the only guard, and it needs a per-harness vocabulary map: ultra is ultracode on claude (rides as xhigh + workflows), ultra on codex (rides as max), INVALID on pi, and config-authored on opencode.
