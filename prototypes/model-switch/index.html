The model-switch prototype: changing a live agent's model, per harness

Every harness claim on this page comes off a real run in this container: a harness in a detached tmux pane, driven blind through the daemon's own paced write path, talking to a local stand-in server that logs every request whole. The model a turn states is read off the wire, never off the pane. findings.md beside this file is the note the build handoff reads.

1 Verdict at a glance

lanemid-session switchrefused modelmeter survives
claude yes — /model <id> + one confirm refused at the switch, API error in the pane yes — same file, message.model flips
codex yes — the /model picker (catalog only) accepted; the NEXT turn fails with the API error yes — same rollout, turn_context.model flips
opencode yes — the /models picker, type-to-filter accepted; the NEXT turn fails with the API error yes — same store, modelID per message
pi yes — the /model picker, type-to-filter accepted; the NEXT turn fails with the API error yes — same session file, model_change events

One hazard holds on all four lanes: a command typed into a non-empty composer concatenates with the queued text and goes to the model as prose. The cure is the same everywhere — Ctrl+U cuts the composer, the switch runs, then the queued text goes back: Ctrl+Y pastes it on claude, codex and pi, and on opencode the daemon retypes it.

3 The evidence, per lane

Full detail in findings.md. Raw pane captures and wire logs sit under evidence/.

claude 2.1.220 · POST /v1/messages

  • Switch: /model <id> typed blind, one confirm. The CLI validates the target with a one-token completion FIRST, so a refused model never lands.
  • Survives: full history on the next request; one session JSONL throughout; composer text via the cut-and-paste discipline.
  • Readback: /status says the model, the transcript states message.model per turn — the exact field the meter reads. The footer at rest shows no model.
  • Hazard: the switch writes the model into the config dir's settings.json, so a bare resume keeps it. The spawn template's --model flag beats it, so the daemon's routing pick always wins a respawn.

codex 0.146.0 · POST /v1/responses

  • Switch: the /model picker only — arrows + Enter, then the effort submenu. The picker lists the built-in catalog alone; /model <id> with an argument goes to the model as prose.
  • Out-of-catalog: kill + codex resume --last -m <id>. The flag beats the session record, which beats config.toml.
  • Survives: full history after the switch; one rollout file; turn_context.model states the model per turn. The footer shows <model> <effort> permanently.
  • Hazard: any model is accepted at the switch; a refused one fails the NEXT turn with a pane error, and that turn is lost. The daemon must refuse cooled or unknown targets before driving the pane.

opencode 1.18.18 · POST /v1/chat/completions

  • Switch: the /models picker — a SEARCH box filters the config's models, Enter picks. No confirm; the footer flips at once.
  • Survives: full history after the switch; one session in the store; opencode.db records modelID per assistant message. Ctrl+U clears the composer, but there is NO paste-back — the daemon retypes.
  • Resume: the strictest lane. The resumed session ALWAYS continues on its own last model: --model, the config and the state file all lose. A switch made in the pane is durable by itself.
  • Hazard: any model is accepted at the switch; a refused one fails the NEXT turn with the API's message in the pane, and that turn is lost.
