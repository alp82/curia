The meter, claude lane no misread

#530 assumed subagent usage lands in the parent transcript as isSidechain lines, and the last line wins. The live run disproves the layout: the parent file holds 140 usage lines, none sidechain. The subagent wrote its own file, two directory levels deeper than the daemon's walker reads.

claudeTail → 99,192 tokens (the parent's own last request)
subagent's last line → 27,841 tokens, in a file the meter never lists

The meter, codex lane misread proven

spawn_agent starts a second session with its own rollout file. findTranscript picks the newest rollout by mtime, so while the child runs, the meter reports the child. The daemon's own code, sampled four times a second during the run (parent scripted to 111,111 tokens, child to 2,222):

20:04:05.9 — no rollout yet 20:04:06.6 parent tokens: — 20:04:06.9 CHILD tokens: 2,222 ← the misread 20:04:07.1 parent tokens: 111,111

In a real delegation the parent waits minutes, and the line shows the child's small context for that whole window.

The fix key is clean: a child rollout's first line says thread_source: "subagent" and names its parent thread. A root session says thread_source: "user". Skipping subagent rollouts in the walk keeps the parent on the line. Per #530 the fix itself belongs to #545.

The bounds orders travel

Claude: the subagent quoted the standing-orders heading and the write-only rule back from its own context. The config-dir CLAUDE.md loads into subagents.

Codex: the child's first user message on the wire is the AGENTS.md block — sentinel found — even with fork_turns: "none".

Nothing mechanical blocks a subagent write outside the bounds on either lane. The claude probe wrote outside /workspace with exit 0. The codex child wrote outside its worktree unhindered. The bounds bind a subagent exactly as they bind the parent: as prose, plus the review gate. The claude subagent flagged the conflict unprompted and deleted the probe file.
