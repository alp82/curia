Why it survives

The reason is structural, read off the wire. Codex rebuilds its developer prefix fresh on every request. The catalog is world state, not conversation. A compaction cuts conversation only. The first request after a compaction:

What follows for curia

  • Nothing has to be rethought. The pointer re-arms on every turn, before and after any number of compactions.
  • The dispatch anchor survives. Codex keeps the first user message verbatim, so a dispatch never loses the line that names prompt.md.
  • Skill bodies do not survive. A skill file read is conversation, so a compaction cuts it. The catalog pointer then tells the model to read the file again. That is the mechanism working as designed.

What this does not answer

  • A real model's choices after a compaction. The stub scripts the model, so re-read frequency after a cut needs a credential, as #461's frequency did.
  • The TUI lane. This is codex exec plus resume, the lane curia dispatches on.
  • A future codex. The rebuild lives in the CLI, so a version bump owes a re-run. The probe is committed beside this page.
