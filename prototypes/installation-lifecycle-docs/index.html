Canonical operator runbook

Install and operate Curia

This runbook takes one Curia installation through its complete supported lifecycle. Read in order for a new host, or use the contents to return to an operation.

Ubuntu 24.04 or Debian 13x86-64Non-root operator30-minute active-work target
01

Prepare the host

Confirm host support, capacity, Docker Engine, Docker Compose, Tailscale, and account authority.

  1. Verify the supported host

    Use Ubuntu 24.04 LTS or Debian 13 on x86-64 with at least 2 CPU cores, 4 GB RAM, and 15 GB free disk.

  2. Verify host-managed services

    Docker and Tailscale must work for the non-root operator. Curia doesn't install or reconfigure them.

    docker version && docker compose version && tailscale status
02

Install and connect Curia

Run the verified bootstrap, then complete browser setup in any service order.

  1. Run the versioned Bash bootstrap

    The bootstrap verifies the release manifest and installs the pinned lifecycle runtime.

    # Illustrative only
    bash ./curia-install-X.Y.Z.sh
  2. Connect GitHub, Discord, Tailscale, and a model provider

    Curia hands external consent to official sites and verifies each current connection.

  3. Run the first Full loop

    Use one marked Rehearsal ticket. Keep the resulting GitHub and Discord links as acceptance evidence.

03

Operate Curia

Use the same launcher for routine status, service control, and direct diagnostics.

  1. Check the installation

    Run curia doctor for redacted, read-only checks. Retry the named failed step after correction.

  2. Use the browser and Discord

    Watch frontier work, dispatch agents, answer questions, and inspect results.

04

Change the installation

Update or roll back through one verified release contract.

  1. Update to the recommended stable release

    Run curia update. Curia stages and verifies the release before it switches services.

  2. Roll back when needed

    Run curia rollback to use the one retained, health-checked release.

  3. Migrate the current source deployment once

    Use the separate versioned cutover runbook. This path isn't a general migration feature.

05

Remove Curia

Choose preservation or confirmed local deletion. External cleanup stays explicit.

  1. Uninstall and preserve identity

    curia uninstall removes runnable resources and preserves config/, secrets/, state/, and work/.

  2. Purge local Curia data

    Confirmed purge removes the complete installation root and matching Curia resources.

  3. Review external cleanup

    Use the reported checklist to revoke or remove provider resources where required.

06

Troubleshoot by observed failure

Find the command and message, apply one corrective action, then retry the current step.

  1. Preflight or lifecycle command failed

    Read the observed host or artifact problem and run the stated correction.

  2. A service connection failed

    Return to that service card, correct the provider-side state, and select Try again.

  3. Curia is installed but unhealthy

    Run curia doctor. The command checks without repairing or retaining diagnostic history.
