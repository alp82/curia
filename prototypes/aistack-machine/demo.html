The aistack machine: register the curia box and sync its tokens

The box registered as machine curia.sh and published one real 30-day reading to aistack. Every step ran headless except the one browser approval.

1 · The registration

One headless device-code login. The box printed a code, the operator approved it in a browser, the CLI saved the token.

box$ npx -y @use-aistack/cli@0.7.2 login ● CODE T72NNC ● OPEN https://aistack.to/cli/auth?code=T72NNC ◒ Waiting for approval... ◇ Authenticated ◆ Token saved.

The answer is both: a one-time act (the approval binds the machine name and the stack) and a credential (a 64-character bearer, returned once). The credential landed in $HOME/.config/aistack/credentials.json. The CLI reads it from that file only, so the build home is the same file under curia's durable HOME: home/.config/aistack/credentials.json, on box disk, never committed.

2 · The reading

The CLI computed the 30-day rolling window from this agent's real transcripts under /cfg/projects. A local cross-check with the same dedup rule agrees:

All on claude-fable-5, one agent session, window from 2026-07-25. The transcript grows while the prototype measures it, which is the whole gap between the two rows.

Double-count, tested live. The operator synced the box into their own stack. As the research predicted: no double-count, but replacement. The box's snapshot replaced their personal Claude Code numbers, and their next personal sync replaces it back. The build must give the box its own stack.

3 · The push

The interactive sync refuses a shell without a TTY. The box path is the silent one:

box$ npx -y @use-aistack/cli@0.7.2 sync --auto on ◆ Auto-sync is on. It runs about every 24h ... box$ npx -y @use-aistack/cli@0.7.2 sync --auto (silent, exit 0) box$ cat ~/.config/aistack/sync.log 2026-08-23T13:23:46.501Z ok - published https://aistack.to/stacks/alper-ortac-unw0sl

After the push the stack's measured layer carries the box's reading as its current Claude Code snapshot, with curia.sh on the machines list. The operator read the page, and their confirmation is on the ticket thread.

4 · The seam for later

The recurring sync needs a linked token, the standing opt-in, and a timer. The right runner is the daemon. The no-clock rule (#345) refuses a clock that files tickets. A sync publishes a reading and files nothing, so it sits with the image prune and the liveness sweep: recurring work inside the daemon.

  • HOME=<workspace_root>/home, so the credential lives in curia's durable home.
  • CLAUDE_CONFIG_DIR built per run: every cfg/* dir, joined with commas.
  • A pinned CLI version. The stock hook runs @latest, which drifts silently.

Bounds: teardown deletes finished sessions' transcripts, so a sync understates the true 30 days. Codex takes one root dir, so its rollouts cannot aggregate across cfg dirs in one scan.
