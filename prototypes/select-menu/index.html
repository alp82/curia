The select menu, built and judged

Does a Discord select menu read better than a numbered list on a phone? Pick an option count below. The same choice card is drawn twice: as the daemon draws it today, and as this branch draws it.

How many options

The button cap is 23. The menu reaches 100. Both edges are in the row.

Today on main

This branch #431

The rule

OptionsSurfaceWhy
2-23 Buttons A button is one tap and a menu is two. Buttons keep the short list.
24-100 Select menu 25 options per menu, four menu rows. The fifth row keeps the preview, timeline and terminal links.
101+ Numbered list The menu cannot hold them. A card that drops option 101 in silence is worse than a card that scrolls.

What the menu cannot show

  • An option shows 100 characters of label and 100 of description. A longer option spills its tail into the description, so 200 characters ride the menu whole.
  • Past 200 characters the menu clips. Then the numbered list stays under it and carries the full words. The menu carries the tap. Pick the 24-option count to see that card.
  • The typed number still answers. The reply path in the bridge is unchanged, so an old card and a stale phone both still work.

The verdict

This page is the design. The verdict is taken on a real card in the ticket thread, after the merge and the deploy. It goes into the resolution comment on #431.
