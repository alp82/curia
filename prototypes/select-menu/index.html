The select menu, built and judged

Does a Discord select menu read better than a numbered list on a phone? Pick an option count below. The same choice card is drawn twice: as the daemon draws it today, and as this branch draws it. Every menu here opens on one tap and answers on one more.

How many options

Buttons hold 4. The menu holds 25. Both edges are in the row.

Today on main

This branch #431

The rule

Three bands. The operator set both edges on #431.

OptionsSurfaceWhy
2-4 Buttons Five buttons fill a row. A card that wraps into a wall of blurple is what the menu stops.
5-25 Select menu 25 is Discord's cap on one menu. It is also as many options as a person picks by reading.
26+ Numbered list The menu cannot hold them. A card that drops option 26 in silence is worse than a card that scrolls.

What the menu cannot show

  • An option shows 100 characters of label and 100 of description. A longer option spills its tail into the description, so 200 characters ride the menu whole.
  • Past 200 characters the menu clips. Then the numbered list stays under it and carries the full words. The menu carries the tap. Pick the third count to see that card.
  • The typed number still answers. The reply path in the bridge is unchanged, so an old card and a stale phone both still work.

The verdict

This page is the design. The verdict is taken on a real card in the ticket thread, after the merge and the deploy. It goes into the resolution comment on #431.
